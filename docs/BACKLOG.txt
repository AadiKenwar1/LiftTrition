BILLING
-------
- Cache last-known hasPremium in AsyncStorage (per-user key), hydrate at
  startup, overwrite when RevenueCat responds. Then remove billingLoaded from
  the allContextsLoaded gate in app/_layout.tsx. Rationale: the gate holds the
  whole app on RevenueCat (15s worst case), and when RevenueCat fails fast the
  gate opens with the wrong state anyway - so it only prevents flicker on the
  happy path. Caching keeps flicker prevention without the startup cost.
  (Offline behavior of the RevenueCat listener is unverified - test on device
  whether cached entitlements arrive without network before assuming lockout.)

DATA INTEGRITY (CODE_REVIEW section 5)
--------------------------------------
- Fail-closed getPendingUploadEstimate plus a shape-pinning test. An unknown
  SDK stats shape currently reads as 0 pending and lets sign-out wipe unsynced
  data. Smallest fix, highest stakes on this list: return null on unknown
  shapes (flushUploadsOrThrow already treats null as not-empty).
- Connector silent PATCH drop (Connector.ts line 194): insert the settings row
  instead of bare return. Reachable scenario is narrow (remote row missing, or
  RLS silently blocking the lookup, while a local edit exists), but when it
  hits, the loss is silent. Cheap insurance.
- Offline first-launch timeout: contexts await waitForFirstSync() bare with no
  timeout anywhere; a fresh install with no connectivity can spin forever.
  Race against a timeout and add a retry state. Verify on device first.
- PowerSync watch queries (or a foreground refresh). Fresh sign-in does pull
  remote data (loads run after first sync), but changes that sync down
  mid-session are invisible until app restart. Matters once multi-device is
  a story.
