# Issue 16 — The safety tests for adding, renaming, and archiving workouts were checking the wrong code

**What you'd have noticed**
Nothing directly — every screen that adds, duplicates, renames, notes, reorders, archives, and unarchives a workout was already working correctly day to day. The problem was invisible in a more worrying way: the automated tests that exist specifically to catch a broken "add workout" or "archive workout" before it ever reached your phone were all showing green and passing, but they weren't actually checking the code your screens run. They were checking a second, separate copy of that logic that had been written off to the side purely so it could be tested in isolation — and the app itself never called it. If a future change had broken the real add/rename/archive code, those tests would have kept reporting "all good" the entire time, because they were watching the wrong thing.

**Why it happened**
The workout screens have their own built-in code for adding, duplicating, renaming, note-editing, reordering, and archiving a workout. Separately, there was a second, standalone version of that same logic living in its own file, kept around so it could be tested without needing to run the whole app. The two were supposed to behave identically, but they'd drifted apart — most notably around archiving. When you archive or unarchive a workout, it's supposed to jump to the top of its new list (the active list or the archived list) and only shift the *other* items already in that same list. The real screens did this correctly. The standalone, tested copy did not: unarchiving it would shift every other workout, including archived ones that should never move, and archiving it never moved the workout to the top of the archived list or shifted its archived neighbors at all. Because the tests only ever exercised that standalone copy, they couldn't have caught a real bug even if one had existed, and on top of that, they were checking for the wrong behavior to begin with.

**What we changed**
We merged the two copies into one. The workout screens now call the exact same underlying code the tests check for every one of these actions: add, duplicate, rename, edit note, reorder, and archive/unarchive. Nothing about saving your data to your device changed — only the part that decides what the screen shows immediately now runs through the tested code instead of a hand-duplicated version of it. We also corrected that shared code's archiving behavior to match what the real screens always correctly did: unarchiving only shifts other active workouts, archiving only shifts other archived workouts, and either way the workout you toggled always lands at the very top of its new list.

**How we know it works**
We first rewrote the automated tests to describe the correct behavior — archiving a workout should put it at the top of the archived list and only bump other archived workouts; unarchiving should only bump other active workouts; and adding a new workout should never shift an archived one out of place. We ran those new tests against the old, untested copy of the logic first and confirmed they failed, which proved they were actually checking something meaningful rather than rubber-stamping whatever the code did. After making the fix, every one of those tests passes, along with the full existing set of 44 workout-function tests and the 8 tests that check workouts, exercises, and logs working together end to end — 52 tests in total, all green. We also manually walked through adding, duplicating, renaming, note-editing, reordering, archiving, unarchiving, and deleting a workout in the app, and it behaves exactly as it did before, since the real behavior didn't change — only which copy of the code produces it.

**Files touched**
- `context/WorkoutContext/functions/workoutFunctions.tsx` — the standalone workout code now matches what the app actually does, especially around archiving order.
- `context/WorkoutContext/functions/__tests__/workoutFunctions.test.ts` — new tests describe the correct archiving and reordering behavior.
- `context/WorkoutContext/index.tsx` — the workout screens now call the same tested code instead of their own hand-duplicated version of it.
