HOW TO READ THIS FILE
  Every issue from the audit is restated in 1-2 plain sentences and tagged:

    [Difficulty]  <ID>  (Severity)  [flags]   route: <agent(s)>

  Difficulty = how much design thought the FIX needs (independent of severity):
    Deep     - needs real thought: many call sites, shared/duplicated logic,
               concurrency, data-migration ordering, or a contract to preserve.
    Moderate - localized but non-obvious: one file/flow, a few edge cases.
    Trivial  - mechanical/copy/token/one-liner, no real blast radius.

  Severity is carried verbatim from the audit (Critical / High / Medium / Low).

  Flags:
    LAUNCH-BLOCKER  - must be fixed (or verified) before submission, even if the
                      fix itself is Trivial. Do not let it get lost.
    -> coordinator  - targeted by >1 agent; each domain agent writes a brief, then
                      the coordinator merges them into one reconciled fix.

  Routing agents: security-cost, logic-correctness, ui-ux, infra-reliability,
  performance, code-structure  (+ coordinator for multi-agent issues).

PLAN
  - DEEP + MODERATE issues (58) get a full agent-authored fix brief in Step 2.
  - TRIVIAL issues (24) do NOT get an agent; their one-line fix note is inline
    below (few-word "why easy" + the fix in a phrase).

[Deep] C1  (Critical)   route: security-cost
  What: Both the AI-vision and food-search Edge Functions do one auth check and then
        call the paid provider (OpenAI/Gemini/FatSecret) with no rate limit, quota, or
        cap, so any free account can script the most expensive path in a loop and run up
        unbounded API spend.
  Files: lib/supabase/functions/fetchOpenAI/index.ts:162-206; fetchFoodDB/index.ts:47-98

[Deep] C3  (Critical)   route: logic-correctness
  What: If a setting changes while a save is in flight, a ref that guards saving sticks
        "true" forever, so every later settings change lives only in memory and is lost
        on app kill — for the whole session, silently.
  Files: context/SettingsContext/index.tsx:148-191

[Deep] H1  (High)   route: security-cost
  What: Premium is enforced only by a local "if (!hasPremium)" in the client; the Edge
        Functions never check entitlement, so a direct HTTP call gets AI scan / macros /
        food search for free — and this is what makes C1 free to exploit.
  Files: context/BillingContext/index.tsx:133; cameraScreen.tsx:35; addNutritionModal.tsx:62; foodDBModal.tsx:30,93

[Deep] H2  (High)   -> coordinator   route: infra-reliability + logic-correctness + code-structure
  What: The PowerSync Connector only dead-letters two error classes; any other permanent
        error retries forever and wedges all syncing (only escape = force sign-out = data
        loss), while a custom-exercise unique-conflict silently drops the row. The branches
        are hand-duplicated and "any"-typed, so every new table risks repeating this.
  Files: lib/powersync/Connector.ts:10,15-24,116,181-188; FlushUploads.ts:73

[Deep] H4  (High)   route: infra-reliability
  What: Production observability is near-zero — only 3 Sentry capture sites, no breadcrumbs,
